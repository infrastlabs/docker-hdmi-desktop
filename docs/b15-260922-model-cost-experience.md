# b15-260922 | 模型积分成本与体验对比

> 背景：2026-09-22 整理 mHub 平台（商汤 API 平台）各模型在实际使用中的积分倍数、响应稳定性与心智表现，作为日常选型与省积分参考。数据来源于本日对话体验，非官方报价，可能随平台调整变化。
> 平台配额限制：每周 60,000 积分、每月 600,000 积分；DS V4 Flash 轻会话单轮积分消耗基数约 85。

## 一、积分倍数与体验

### 1、积分倍数对比（以 DS V4 Flash 为基准）

| 模型 | 倍数 | 备注 |
|------|------|------|
| DeepSeek V4 Flash | 1× | 基准档，最省；轻会话单轮积分基数约 85；与 pro 共享 24h 内缓存（重复上下文命中红利） |
| DeepSeek V4 Pro | 4× | 慢；与 flash 同挤队列，8月底起常限流失败；缓存与 flash 共享，性价比差 |
| GLM-5.2 | 12× | 常规编码/中等复杂度任务可用，但日常闲聊也按此消耗，不划算 |
| Kimi K3 | 25× | 最贵；速度慢、与 flash 同挤队列、8月底起限流失败；适合复杂架构/深度推理/微妙 bug |
| sense6.8-flash-lite | 2× | 9月上旬响应卡死、体验极差，当前（9月下旬）流畅；从 6.7 升级而来，6.7 体验与心智均良好；**上下文仅 256K**，长文档/大仓库需切片 |

### 2、选型务实建议

- **日常 + 高重复上下文 → DS V4 Flash**：缓存命中率高时性价比拉满，bash/Dockerfile/文档/简单问答均能胜任。
- **sense6.8-flash-lite（2×）**：日常可用，心智够；注意 256K 上下文截断，分析大文件/大仓库时不如 Flash 缓存红利。
- **GLM-5.2（12×）**：偶尔用于中等复杂度任务，避免日常闲聊消耗。
- **Kimi K3（25×）**：仅在啃不动的硬骨头（复杂架构、诡异 bug、长链推理）时临时切，且尽量一次到位，减少往返触发限流。

### 3、限流与稳定性备注

- 8月底起，pro / flash / k3 等档位用户任务拥挤，常限流失败；DS V4 pro 因同样挤队列且慢，倍数虽仅 4× 但体验不佳。
- sense6.8-flash-lite 在 9月上旬出现响应卡死，9月下旬已恢复流畅。
- 通用对策：**指令具体化、合并任务、减少模型往返试探**，可同时降低积分消耗与限流触发概率。

### 4、备注

- 模型均接入商汤 API 平台；平台积分配额：每周 60,000、每月 600,000，超限需等下一周期。
- 倍数为体验实测口径，非官方价目；缓存命中会显著拉低实际成本，故 Flash 实际开销可能远低于标称倍数。
- 后续若平台调整价格或新增档位，在本表追加并标注日期即可。
