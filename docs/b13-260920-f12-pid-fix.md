# 环境分析：PID 数量暴涨（f12 监听轮询 fork 风暴）

> 日期：2026-09-20
> 环境：`/_ext/home/headless`（Linux 容器，tini 为 PID 1，perpd 管理服务）
> 关联修复：commit `d0ba889`（f12_to_tty1.sh）、`3e8d508`（f12_single.sh）

## 结论

PID 计数器暴涨不是 maki/agent 或正常工具调用导致，而是常驻的 **F12 键盘监听脚本 `f12_to_tty1.sh` 内部轮询缺陷**：监听子 shell 用 `grep + sleep 0.05` 轮询代替事件驱动，每键盘约 40 fork/秒，且随日志增长呈突发性。

## 现状数据

| 指标 | 值 |
|---|---|
| `ns_last_pid`（容器已分配 PID） | 1,577,498（启动 ~20h） |
| `pid_max` | 4,194,304 |
| 实测 PID 分配速率 | ~42 个/秒（突发）↔ ~3 个/秒（空闲），平均 ~22/秒 |
| 进程总数 | 66（不含短命进程） |
| 僵尸进程 | 0 |
| 负载 / 内存 | 0.44 / 30GiB 用 3.8GiB（健康） |

## 进程树与根因链

```
perpd(254) ── bash(266): while true; do sleep 1; bash /usr/local/bin/f12_to_tty1.sh; done
               └─ bash(339) = f12_to_tty1.sh 实例（阻塞等 F12，不退出）
                    ├─ 主循环: sleep 0.2            → 5 fork/秒
                    └─ bash(346) = 监听子 shell（ps 显示为脚本 cmdline，易误认）
                         ├─ evtest(347) 读 /dev/input/event1
                         └─ 轮询: grep + sleep 0.05 → ~40 fork/秒 ← 主要消耗
```

三个要点（含分析过程中的修正）：

1. **外层 `while true; do sleep 1; bash …; done` 并非每秒重启**：bash 顺序阻塞，脚本等 F12 永不退出，外层一直 `wait` 在脚本上，只在脚本退出后（F12 触发 chvt 后）1 秒重启一次，属正常韧性设计，**无需改动**。
2. **真正的 PID 消耗源是监听子 shell 的轮询**：`while ! grep -qm1 -E …; do sleep 0.05; done` 每次迭代 fork `grep` + `sleep` 两个进程，0.05s 一轮 = 每键盘 ~40 fork/秒。速率波动（42/s ↔ 3/s）源于 grep 扫描日志耗时随日志变大而变化。
3. `evtest | grep -m1` 管道本身有 SIGPIPE(141)/阻塞挂起 bug（见 docs/b6-260917-f12-chvt-fix.md），此前改为"写日志 + 0.05s 轮询 + 显式 kill"，把 CPU 开销换成了 fork 风暴。

## 后果

- 20h 已消耗 158 万 PID；按平均 22/秒，再过 ~1-2 天撞上 `pid_max` 4M 并回绕。
- 回绕时若大量 PID 未释放，内核需线性扫描找空闲号，新进程 fork 变慢/抖动，其他程序可能偶发 `Resource temporarily unavailable`。

## 修复（已提交）

监听子 shell 改为 **coproc 事件驱动直读 evtest 输出**：`read` 阻塞等行、匹配 `KEY_F12 value 1` 才动作，显式 `kill + wait` 防挂起/残留，**零轮询零 fork**；主循环用 `read -t` 内建阻塞（无人 fifo）替代外部 `sleep`。

- `d0ba889` fix(f12_to_tty1.sh)：监听 coproc 事件驱动 + 主循环 read -t
- `3e8d508` fix(f12_single.sh)：同步 coproc 事件驱动

预期空闲 fork：42/s → ~0/s。已验证：coproc 匹配→break→kill→清理路径在容器 bash 5.2 实测通过。

## 注意

- perpd 是服务管理器，直接 kill 旧进程会被自动拉起；先替换脚本再重启服务。
- 脚本在 `/usr/local/bin`（需 root 写）；当前用户为 `headless`（uid=1000，在 sudo 组，免密）。
